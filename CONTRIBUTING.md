# Contributing

Thank you for your interest in this research repository.

This project contains published-preprint companion material together with post-preprint conceptual, formal, ontological, and technical developments. Contributions are welcome, but changes to the repository are subject to maintainer review and approval.

## Ways to contribute

Useful contributions include:

- conceptual clarification, criticism, and counterexamples;
- formalization and Lean developments;
- ontology modeling and mappings;
- Concept-Rule Base (CRB) and OMCR specifications;
- bibliographic corrections and relevant literature suggestions;
- documentation, diagrams, and reproducibility improvements;
- experimental implementations that are clearly separated from the scientific core;
- reports of technical or formalization errors.

## Issues versus pull requests

Use an **issue** to report a problem, ask a focused research question, propose a change, or discuss a substantial conceptual modification.

Use a **pull request (PR)** when you are proposing concrete changes to repository files.

For major conceptual changes, please open an issue first so that scope, terminology, and scientific status can be discussed before implementation.

## Scientific status must be explicit

Every substantial contribution should distinguish among:

1. correction or clarification of material already present in the associated preprint;
2. post-preprint theoretical development;
3. experimental implementation;
4. speculative research proposal.

Do not present post-preprint developments as if they were claims already established by the published preprint.

## Evaluation criteria

Contributions may be discussed, revised, or declined based on:

- conceptual consistency;
- scientific relevance and repository scope;
- formal correctness;
- provenance and traceability;
- reproducibility where applicable;
- compatibility with the Ontological Mediation framework;
- clarity of distinction between published and post-preprint material;
- appropriate engagement with relevant literature;
- intellectual-property and security considerations.

Claims of novelty should be accompanied by appropriate literature support.

## Intellectual-property caution

The repository follows a distinction between an open scientific core and potentially proprietary implementation details. Before contributing implementation material, consider whether it discloses algorithms, ranking or retrieval mechanisms, indexing strategies, automatic binding procedures, optimization methods, product-specific architecture, or other potentially commercially sensitive engineering details.

If in doubt, open an issue describing the contribution at a high level before publishing implementation details.

## Pull requests

A pull request should:

- explain what is changed and why;
- identify the relevant framework component;
- state the scientific status of the change;
- cite relevant references when substantive scientific claims are involved;
- avoid unrelated changes in the same PR;
- preserve terminology and notation unless the PR explicitly proposes a justified revision.

All pull requests require maintainer review before incorporation into the main branch.

## Editorial authority

Acceptance of a pull request is an editorial and technical decision. It does not by itself constitute scientific validation of every claim contained in the contribution.

The repository maintainer retains final authority over the contents of the main branch.
