# Security Policy

## Scope

This repository currently contains primarily research documentation, conceptual specifications, formal artifacts, diagrams, and evolving experimental material. Software components may be added over time.

## Reporting a security issue

If you identify a vulnerability that could expose data, enable unauthorized access, execute unintended code, compromise dependencies, or otherwise create a security risk, **do not publish exploitable details in a public issue**.

Use GitHub's private vulnerability reporting mechanism for this repository if the **Report a vulnerability** option is available.

If private vulnerability reporting is not available, contact the repository maintainer through the maintainer's GitHub profile before transmitting sensitive details.

## Non-security issues

Conceptual errors, documentation problems, formalization mistakes, reproducibility problems, and ordinary software defects that do not create a security risk should be reported through the standard issue templates.

## Supported material

Because this is an evolving research repository rather than a versioned production software package, no fixed software release series is currently designated as security-supported. This policy may be revised if deployable software components are released.
